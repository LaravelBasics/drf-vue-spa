```
## 🔑 重要なポイント

### Q: CSRF取得したら即座にブラウザに保存？
**A: はい！** Djangoの`@ensure_csrf_cookie`デコレータが、レスポンスヘッダーに`Set-Cookie: csrftoken=...`を付けてくれるので、**ブラウザが自動的に保存**します。

### Q: その後のリクエストでAxiosがcookieから取得？
**A: はい！** `xsrfCookieName: 'csrftoken'`の設定により、Axiosは：
1. ブラウザのcookieから`csrftoken`を読み取る
2. 自動的に`X-CSRFToken`ヘッダーにセットする

### Q: `withXSRFToken: true`の役割は？
**A: クロスオリジン時にcookieを強制的に読み取る設定**

- **開発環境**: `localhost:5173` → `localhost:8000`は**別オリジン**なので`true`必須
- **本番環境**: Nginxのリバースプロキシで**同一オリジン**化されるので不要
```

📚 公式情報に基づく正確なフロー
1️⃣ Django公式: @ensure_csrf_cookieの役割
Djangoでは、テンプレートにcsrf_tokenタグが含まれていない場合、CSRFトークンcookieが自動的にセットされないことがあります。この問題に対処するため、ensure_csrf_cookieデコレータを使ってcookieを強制的にセットできます Django DocumentationDjango。
つまり:
python@method_decorator(ensure_csrf_cookie)
def get(self, request):
    return Response(status=status.HTTP_204_NO_CONTENT)
↓
このデコレータはレスポンスにSet-Cookieヘッダーを含め、CSRFトークンを設定します Django Ninja
↓
ブラウザが自動的にcookieとして保存 ✅

2️⃣ Axios公式: 自動CSRF保護機能
Axiosはデフォルトで、XSRF-TOKENという名前のcookieからトークンを読み取り、非GETリクエストでX-XSRF-TOKENヘッダーに自動的に含めます DEV Community。
Axiosは自動的にブラウザのcookieからトークンを読み取り、リクエストヘッダーに含めることで、サーバーがリクエストの正当性を検証できるようにします DeepWiki。
カスタム設定（Djangoの場合）:
javascriptaxios.defaults.xsrfCookieName = 'csrftoken'  // ← Djangoのcookie名
axios.defaults.xsrfHeaderName = 'X-CSRFTOKEN' // ← Djangoのヘッダー名
これらの設定により、Axiosはcsrftokenという名前のcookieからトークンを読み取り、X-CSRFTOKENヘッダーに自動的にセットします vsupalov.com。

3️⃣ 重要！withXSRFTokenの役割（開発環境で必須）
あなたのコードのここが超重要(´・ω・｀)：
javascriptwithXSRFToken: import.meta.env.DEV ? true : undefined,
```

Axiosバージョン1.6.0以降、withXSRFTokenがundefinedの場合、デフォルトでは同一オリジンのリクエストにのみCSRFトークンを含めます。クロスオリジンリクエストにトークンを含めるには、withXSRFTokenをtrueに明示的に設定する必要があります 。

**なぜ開発環境で`true`が必要？**
- 開発: `localhost:5173` (Vue) → `localhost:8000` (Django) = **別オリジン**（ポートが違う）
- 本番: Nginxのリバースプロキシで**同一オリジン化**されている

デフォルトでは、Axiosはプロトコル、ホスト、ポートを比較して同一オリジンかどうかを判定します 。
```
