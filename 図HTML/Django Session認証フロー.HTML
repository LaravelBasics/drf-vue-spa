ログイン処理の流れ

1
フロントエンドからログインリクエスト
// フロントエンド (Vue.js)
axios.post('/api/login/', { group_id: '1', user_id: 'user123', password: 'pass123' })
📍 ポイント
グループID + ユーザーID + パスワードの3点セットで送信
↓
2
Djangoミドルウェア層を通過
settings.py → MIDDLEWARE
# 通過するミドルウェア（順番重要）
1. CorsMiddleware # CORS設定チェック 2. SecurityMiddleware # セキュリティヘッダー 3. SessionMiddleware # ★セッション読み込み★ 4. CsrfViewMiddleware # ★CSRF検証★ 5. AuthenticationMiddleware # ★認証処理（後で重要）★ 6. MessageMiddleware # Flashメッセージ
⚠️ 重要
この時点では未認証。SessionMiddlewareが既存セッションを読み込むだけ。
↓
3
views.py の LoginAPIView に到達
accounts/views.py
# LoginAPIView
class LoginAPIView(APIView): permission_classes = [AllowAny] # ← ログインなので認証不要 authentication_classes = [CSRFEnforcedSessionAuthentication] def post(self, request): # バリデーション serializer = LoginSerializer(data=request.data) # ★ここで認証開始★ user = authenticate( request=request, username=user_id, # ← user_id渡す password=password, group_id=group_id )
📍 authenticate()の役割
AUTHENTICATION_BACKENDSに設定されたバックエンドを呼び出す
↓
4
カスタムバックエンドで認証
accounts/backends.py
settings.py → AUTHENTICATION_BACKENDS
# settings.py
AUTHENTICATION_BACKENDS = [ 'accounts.backends.GroupUserAuthBackend' # ← これが呼ばれる ]
# accounts/backends.py
class GroupUserAuthBackend(BaseBackend): def authenticate(self, request, username=None, password=None, group_id=None, **kwargs): # ★1. ユーザー取得★ user = User.objects.filter(user_id=username).first() # ★2. パスワード検証★ if not user.check_password(password): return None # ★3. グループ所属チェック★ if not UserGroup.objects.filter( user_id=user.user_id, group_id=group_id ).exists(): return None # ★4. 認証成功★ return user
🔑 ここでmodels.pyの設定が効く
USERNAME_FIELD = 'user_id' により、Djangoはuser_idを主キーとして扱う
↓
5
login()でセッション作成
django.contrib.auth.login()
# views.py に戻る
if user is not None: # ★Django標準のlogin()関数★ login(request, user) # セッションにグループIDも保存（オプション） request.session['current_group_id'] = group_id return Response({'detail': 'logged_in'})
📦 login()の内部処理
1. request.session['_auth_user_id'] = user.user_id をセット
2. request.session['_auth_user_backend'] にバックエンド名を保存
3. セッションをDBに保存（django_sessionテーブル）
4. sessionid Cookie をレスポンスにセット
↓
6
レスポンス返却
// フロントエンドが受け取るレスポンス
{ "detail": "logged_in", "user": { "user_id": "user123", "username": "山田太郎", "is_admin": false, "current_group": { "group_id": "1", "group_name": "営業部" } } } // ★Cookieに sessionid がセットされている★ Set-Cookie: sessionid=abc123xyz; HttpOnly; SameSite=Lax

認証済みリクエストの流れ

1
フロントエンドからAPIリクエスト
// フロントエンド (Vue.js)
// ★sessionid Cookie が自動的に送られる★ axios.get('/api/me/', { withCredentials: true // Cookie送信を有効化 })
🍪 Cookie自動送信
ブラウザが自動的にsessionid Cookieを送信
↓
2
SessionMiddleware がセッション読み込み
django.contrib.sessions.middleware.SessionMiddleware
# SessionMiddleware の処理
1. Cookie から sessionid を取得 2. django_session テーブルから session_data を取得 3. request.session に復元 → request.session['_auth_user_id'] = 'user123' → request.session['_auth_user_backend'] = '...'
↓
3
AuthenticationMiddleware がユーザー復元
django.contrib.auth.middleware.AuthenticationMiddleware
# AuthenticationMiddleware の処理
1. request.session から '_auth_user_id' を取得 2. request.session から '_auth_user_backend' を取得 3. ★バックエンドの get_user() を呼び出す★ # accounts/backends.py def get_user(self, user_id): # ← ここが呼ばれる！ return User.objects.get(pk=user_id) 4. request.user にユーザーオブジェクトをセット
🔑 ここでカスタムバックエンドが効く
get_user()で文字列PKのユーザーを取得
↓
4
DRF の認証・権限チェック
accounts/views.py
# MeAPIView
class MeAPIView(APIView): permission_classes = [IsAuthenticated] # ← ★ここでチェック★ authentication_classes = [CSRFEnforcedSessionAuthentication] def get(self, request): # ★この時点で request.user は認証済み★ serializer = UserSerializer(request.user) return Response(serializer.data)
✅ IsAuthenticated の内部処理
1. request.user.is_authenticated をチェック
2. models.py で定義した@property is_authenticatedが呼ばれる
3. True なら通過、False なら 401 Unauthorized
↓
5
ビュー処理実行
# MeAPIView の処理
def get(self, request): # request.user は完全に復元されている # - user.user_id # - user.username # - user.is_admin # - user.is_authenticated (True) serializer = UserSerializer( request.user, context={'request': request} ) return Response(serializer.data)
↓
6
レスポンス返却
// フロントエンドが受け取るレスポンス
{ "user_id": "user123", "username": "山田太郎", "email": "yamada@example.com", "is_admin": false, "is_active": true, "current_group": { "group_id": "1", "group_name": "営業部" } }

設定の役割とつながり

❌ 標準Django（レガシー不可）
# models.py
from django.contrib.auth.models import User # 標準Userモデル # - username (文字列) # - id (整数の自動採番)
# settings.py
# デフォルト（明示不要） AUTH_USER_MODEL = 'auth.User' AUTHENTICATION_BACKENDS = [ 'django.contrib.auth.backends.ModelBackend' ]
問題点:
・既存テーブルと構造が違う
・user_id（文字列PK）に対応できない
・グループ認証ができない
✅ レガシーシステム対応版
# users/models.py
class User(models.Model): user_id = models.CharField(primary_key=True) # ★これでDjango認証対応★ USERNAME_FIELD = 'user_id' REQUIRED_FIELDS = [] @property def is_authenticated(self): return True def check_password(self, raw_password): return check_password(raw_password, self.password)
# settings.py
# ★カスタムユーザーモデル指定★ AUTH_USER_MODEL = 'users.User' # ★カスタムバックエンド指定★ AUTHENTICATION_BACKENDS = [ 'accounts.backends.GroupUserAuthBackend' ]
これで実現:
・文字列PKに対応
・グループ認証に対応
・IsAuthenticated使える
・Django標準機能全部使える
設定が効くタイミングマップ
# 各設定が使われる場所
┌─────────────────────────────────────────────────────┐ │ AUTH_USER_MODEL = 'users.User' │ ├─────────────────────────────────────────────────────┤ │ 使われる場所: │ │ ・get_user_model() → User モデルを返す │ │ ・login() → User.objects.get(pk=user_id) 実行 │ │ ・request.user → User インスタンスがセットされる │ └─────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────┐ │ AUTHENTICATION_BACKENDS │ ├─────────────────────────────────────────────────────┤ │ 使われる場所: │ │ ・authenticate() → backends.py の authenticate()呼出 │ │ ・AuthenticationMiddleware → get_user()呼出 │ └─────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────┐ │ USERNAME_FIELD = 'user_id' (models.py) │ ├─────────────────────────────────────────────────────┤ │ 使われる場所: │ │ ・authenticate(username=xxx) → user_id で検索 │ │ ・login() → user_id をセッションに保存 │ └─────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────┐ │ @property is_authenticated (models.py) │ ├─────────────────────────────────────────────────────┤ │ 使われる場所: │ │ ・IsAuthenticated → user.is_authenticated チェック │ │ ・テンプレート → {% if user.is_authenticated %} │ └─────────────────────────────────────────────────────┘
💡 まとめ: なぜレガシーシステムでも動くのか？
1. AUTH_USER_MODEL で「どのモデルをユーザーとして扱うか」指定
2. USERNAME_FIELD で「どのフィールドを主キーとして扱うか」指定
3. AUTHENTICATION_BACKENDS で「どうやって認証するか」指定
4. models.pyのメソッド で「Django標準機能との互換性」確保

→ これでDjango標準のsession認証が完全に動く！
→ IsAuthenticated も使える！
→ 文字列PKでもOK！
