and 演算子の基本ルール

🎯 超重要ルール
A and B は以下の順番で評価される：

1️⃣ まず A を評価
2️⃣ A が False なら、もう B は評価しない（短絡評価）
3️⃣ A が True なら、B を評価してその結果を返す
# Python の and 演算子の動き
# ケース1: A が False result = False and True # → A (False) で評価終了 # → B (True) は評価されない # → 結果: False # ケース2: A が True result = True and True # → A (True) なので続行 # → B (True) を評価 # → 結果: True # ケース3: A が True、B が False result = True and False # → A (True) なので続行 # → B (False) を評価 # → 結果: False

IsAuthenticated のコード解説

# DRF の IsAuthenticated
return request.user and request.user.is_authenticated # ───────────── ────────────────────────── # A B
1
Step 1: request.user を評価
# まず A (request.user) をチェック # ケース1: ログイン済み request.user = User('user123') # ← オブジェクトが存在 → Pythonでは「オブジェクトが存在 = True」 → ✅ 次へ進む # ケース2: 未ログイン request.user = AnonymousUser() # ← これもオブジェクト → Pythonでは「オブジェクトが存在 = True」 → ✅ 次へ進む # ケース3: Noneの場合（理論上は起きない） request.user = None → Pythonでは「None = False」 → ❌ ここで終了、B は評価されない → 結果: None を返す
↓
2
Step 2: request.user.is_authenticated を評価
# Step 1 でオブジェクトが存在したので、B を評価 # ケース1: ログイン済み request.user.is_authenticated → User.is_authenticated が呼ばれる → @property で return True → ✅ True を返す # ケース2: 未ログイン request.user.is_authenticated → AnonymousUser.is_authenticated が呼ばれる → 常に return False → ❌ False を返す

完全な真理値表

状態 request.user
(A)		 is_authenticated

ログイン済み User (True) True True ✅ 許可

request.user = None

💡 なぜ and を使うのか？
理由1: 安全性
もし request.user が None だった場合、
request.user.is_authenticated を実行すると AttributeError になる。
and を使えば、None の時点で評価が止まるので安全。

理由2: コードが短い
以下と同じ意味だけど、and の方が短い：
# 長い書き方 if request.user is not None: return request.user.is_authenticated else: return False # 短い書き方（and を使用） return request.user and request.user.is_authenticated

実例: and 演算子の動き

# Python シェルで実験
# 例1: 文字列 and 数値 >>> "hello" and 123 123 # ← "hello"がTrue なので、123 を返す # 例2: 空文字列 and 数値 >>> "" and 123 '' # ← ""がFalse なので、空文字列を返す（123は評価されない） # 例3: None and なんでも >>> None and "hello" None # ← NoneがFalse なので、Noneを返す（"hello"は評価されない） # 例4: オブジェクト and True >>> user = User('user123') >>> user and True True # ← userがTrue なので、Trueを返す # 例5: オブジェクト and False >>> user = User('user123') >>> user and False False # ← userがTrue なので、Falseを評価して返す
🔑 重要ポイント
and は 最後に評価した値をそのまま返す
True/False に変換するわけじゃない！

例:
"hello" and 123 → 123 を返す（True じゃない！）
"" and 123 → "" を返す（False じゃない！）

まとめ

✅ ログイン済み
request.user = User ↓ (True) request.user.is_authenticated ↓ User.is_authenticated ↓ return True ↓ ✅ アクセス許可
❌ 未ログイン
request.user = AnonymousUser ↓ (True) request.user.is_authenticated ↓ AnonymousUser.is_authenticated ↓ return False ↓ ❌ 401 Unauthorized
🎯 最終結論
return request.user and request.user.is_authenticated

これは以下と同じ意味:
1. まず request.user が存在するかチェック
2. 存在したら request.user.is_authenticated を評価
3. その結果（True or False）を返す

短絡評価でエラーを防ぎつつ、認証状態をチェックできる！
