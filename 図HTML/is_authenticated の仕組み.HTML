🔐 is_authenticated の仕組み完全解説

核心: request.user の正体

💡 超重要ポイント
request.user には2種類のオブジェクトが入る可能性がある：
1️⃣ User オブジェクト（ログイン済み）
2️⃣ AnonymousUser オブジェクト（未ログイン）
✅ ログイン済み
# request.user の中身
<User: user123> # request.user.is_authenticated を呼ぶと... → User.is_authenticated が呼ばれる → @property で定義した return True → ✅ True が返る
❌ 未ログイン
# request.user の中身
<AnonymousUser> # request.user.is_authenticated を呼ぶと... → AnonymousUser.is_authenticated が呼ばれる → 常に False を返す（Django内部実装） → ❌ False が返る

AuthenticationMiddleware の動き

1
セッションチェック
# AuthenticationMiddleware の処理
# セッションに _auth_user_id があるか？ user_id = request.session.get('_auth_user_id') if user_id: # ★ログイン済み → Userを取得★ user = backend.get_user(user_id) request.user = user # ← User オブジェクト else: # ★未ログイン → AnonymousUserをセット★ request.user = AnonymousUser() # ← AnonymousUser オブジェクト
↓
2
IsAuthenticated の判定
# IsAuthenticated クラスの内部
class IsAuthenticated(BasePermission): def has_permission(self, request, view): # ★ここで request.user.is_authenticated を呼ぶ★ return request.user and request.user.is_authenticated
✅ ログイン済みの場合:
request.user = User オブジェクト
request.user.is_authenticated = True
→ 通過
❌ 未ログインの場合:
request.user = AnonymousUser オブジェクト
request.user.is_authenticated = False
→ 401 Unauthorized

AnonymousUser の実装（Django内部）

# django/contrib/auth/models.py
class AnonymousUser: """未ログインユーザーを表すクラス""" id = None pk = None username = '' is_staff = False is_active = False is_superuser = False # ★重要: is_authenticated は常に False★ @property def is_authenticated(self): return False # ← 常にFalse！ # ★重要: is_anonymous は常に True★ @property def is_anonymous(self): return True # ← 常にTrue！
🔑 ポイント
Djangoは未ログイン時にNoneではなくAnonymousUserをセットする。
これによりrequest.user.is_authenticatedが常に安全に呼べる。

実際の動作比較

状態 request.user の型 is_authenticated IsAuthenticated
ログイン成功後 User True ✅ 通過
ログアウト後 AnonymousUser False ❌ 401
初回アクセス AnonymousUser False ❌ 401
セッション期限切れ AnonymousUser False ❌ 401

視覚的に理解

✅
ログイン済み
request.user → User('user123') → .is_authenticated → return True → IsAuthenticated: ✅ PASS
❌
未ログイン
request.user → AnonymousUser() → .is_authenticated → return False → IsAuthenticated: ❌ 401

実際のコード例

# views.py
class MeAPIView(APIView): permission_classes = [IsAuthenticated] def get(self, request): # ★この時点で既にIsAuthenticatedを通過★ # つまり request.user は 100% User オブジェクト # AnonymousUser の可能性はゼロ print(type(request.user)) # ログイン済み: <class 'users.models.User'> # 未ログインはここに来れない（401で弾かれる） return Response({ 'user_id': request.user.user_id, # ← 安全に使える 'username': request.user.username })
# 未ログイン時のリクエスト
GET /api/me/ → AuthenticationMiddleware → request.session に _auth_user_id なし → request.user = AnonymousUser() → IsAuthenticated.has_permission() → request.user.is_authenticated == False → ❌ return False → DRF が 401 Unauthorized を返す → views.py の get() は実行されない

まとめ

🎯 結論
@property def is_authenticated(self): return True は
「Userオブジェクトが存在する場合は常にTrue」という意味

なぜ常にTrueじゃないのか？
→ 未ログイン時はAnonymousUser.is_authenticatedが呼ばれるから
→ AnonymousUserは常にFalseを返す
→ だからIsAuthenticatedが正しく動作する
✅ この設計の利点:
・request.userが常に存在する（Noneチェック不要）
・request.user.is_authenticatedが安全に呼べる
・ログイン済み/未ログインをシンプルに判定できる
